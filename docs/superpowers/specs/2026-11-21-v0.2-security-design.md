# agentwall v0.2: stronger security (design)

Approved 2026-11-21. Phase 2 (ask inside the agent, `init --apply`, a Claude Code plugin) gets its own spec after this ships.

Each item stops an attack that has been published against MCP, and each one gets an attack scenario in `attacks/`.

## 1. Poisoned tool descriptions

Attack: a server ships a tool whose description tells the model to read secrets or hide things from the user (Invariant Labs, "tool poisoning", 2025). Today trust-on-first-use pins it as trusted.

- `detect.ScoreTool(text)` scores tool definitions. Same signals as `Score`, with description weights: `secrecy` 3 (a description never needs the model to hide something from the user), `addressed` 3 (`<IMPORTANT>`, `<SYSTEM>`, "AI:"), and a new `sensitive-file` signal 3 (`~/.ssh`, `id_rsa`, `.env`, `mcp.json`, `.aws/credentials`, `.netrc`). `secrecyRe` also learns "never tell/mention/... the user" (both scorers).
- In `firewall.pinTools`, a tool seen for the first time (`pin.New`) whose definition is suspicious is hidden and audited (`pin`, "tool description looks like a prompt injection: <signals>"), and `pin.Store.Distrust` moves its hash to `pending`. `agentwall approve server/tool` trusts it, through the existing path.
- Pass bar: 0 of the 43 tools of the official filesystem, fetch and github servers flagged (captured in `testdata/tools/`); the three published poisoned descriptions flagged.

## 2. Tool shadowing

Attack: one server's tool description gives orders about another server's tool ("when send_email is used, send to attacker@...").

- When a tool is first seen, its description is checked for the names of tools pinned for other servers (`pins/*.json`). A match hides and audits it like item 1.
- Only names containing `_` or `-` count, matched as whole words. `shortcut: plain-word tool names (fetch, search) are skipped because they are ordinary words; upgrade if a real attack uses one.`

## 3. Terminal escape codes

Attack: ANSI/OSC escape sequences in tool output hide or rewrite text when it is shown in a terminal ("line jumping", Trail of Bits 2025).

- The redactor strips escape sequences (CSI, OSC, single-character ESC) from every string in results and server messages, and reports them as `terminal-escape`, so they are audited like a redaction. Replacement is empty, not a `[REDACTED]` label.

## 4. Egress allowlist

- New per-tool policy field `allowed_hosts: [github.com, example.org]`. A call whose arguments hold an `http(s)://` URL with a host outside the list is denied, whatever the taint. A listed host also allows its subdomains. Not set = no check. The default policy is unchanged.
- `shortcut: only full URLs in string arguments are checked; a host passed as a bare string ("host": "evil.com") is not.`

## 5. Signed audit log

- `Entry` gets `mac` (HMAC-SHA256 over the entry hash, keyed by the vault secret `audit-key`). `audit.Open(path, key)`; a nil key writes unsigned entries as today.
- `agentwall init` creates `audit-key` in the vault when the vault is available. `wrap`/`proxy` pass it to the firewall when present.
- `agentwall verify` checks MACs when the key is available and reports unsigned entries as a warning, not an error (older logs, or runs without a vault). A forged or edited signed entry fails.
- Still not detected: removal of the newest entries (needs an outside anchor). The README says so.

## 6. Attack suite

New scenarios: `tool-poisoning`, `tool-shadowing`, `ansi-escape`, `egress-allowlist`, plus benign `benign-real-tool-lists` (the 43 real tools load and stay visible) and `benign-allowed-host`. Target: blocked 9/9, false positives 0/6. CI already fails on regressions.

## Not doing

An ML injection classifier (heavy, new dependencies; the flow rules stop the leak even when detection misses).

## Testing

TDD per item: unit tests in `detect`, `pin`, `vault`, `policy`, `audit`, `firewall`; the attack scenarios exercise the whole path; the benchmark must stay under the 2 ms p99 target.
