# agentwall v0.3: easy to use (design)

Approved 2026-11-22. Goal: a beginner installs agentwall from Claude Code in two commands, every MCP server ends up behind it without hand-editing configs, and an `ask` rule shows its question inside the agent.

## 1. `ask` through MCP elicitation (stdio)

- `firewall.onRequest` remembers whether the client declared `capabilities.elicitation` in `initialize`. If it did, an `ask` decision returns `proxy.Decision{Ask: question, Reason}` instead of calling `TerminalAsk`; otherwise behaviour is unchanged (terminal, else deny).
- `proxy.Run` sends the agent `elicitation/create` with id `agentwall-<n>`, a message naming the server, tool and reason, and a schema with one required boolean `allow`. The agent read loop keeps running while the question is open.
- Ends, whichever comes first (one winner, under the proxy mutex):
  - answer `action: accept` with `allow: true`: the call is registered as pending and forwarded upstream;
  - any other answer (decline, cancel, `allow: false`): the agent gets the usual -32001 blocked error;
  - 5 minutes without an answer: blocked;
  - the agent cancels the call (`notifications/cancelled` with its id): no reply, nothing forwarded.
- A late answer to an ended question is dropped. Responses with an `agentwall-` id never go upstream.
- `Hooks.OnAnswer(req, approved bool, why string)` lets the firewall audit the outcome (`allow`/`deny`, "approved in the agent", "declined in the agent", "no answer in 5 minutes").
- `shortcut:` HTTP mode keeps the terminal prompt; asking over HTTP needs the server-to-client stream.
- Before the Go code: `spec/Ask.tla` models the flow (answer, timeout and cancel racing; late answers) and TLC checks that a call reaches upstream only after an accept, that every call gets at most one reply, and that every question ends. A broken variant (the timeout does not clear the question) must fail.

## 2. `agentwall init --apply` and `--check`

- `--apply` rewrites the MCP configs `init` already finds (`./.mcp.json`, `./.cursor/mcp.json`, `~/.cursor/mcp.json`, and in `~/.claude.json` both the user-scope `mcpServers` and `projects[<cwd>].mcpServers`) so every stdio server runs as `<absolute path to agentwall> wrap --server <name> -- <command> <args...>`. `env` and every other key are kept. Already wrapped servers are left alone, so a second run changes nothing.
- Each file is backed up to `<file>.agentwall-backup-<UTC timestamp>` before it is written (write to a temp file, then rename). The output names the backup and says to restart the agent.
- HTTP servers get the printed `agentwall proxy` instructions, as today.
- `--check` prints one line per unprotected stdio server and nothing when all are protected (exit 0 either way; it feeds the plugin hook).

## 3. Claude Code plugin

- `.claude-plugin/marketplace.json` at the repo root makes the repo a marketplace with one plugin, `agentwall`, in `plugin/`.
- `plugin/skills/setup/SKILL.md` (`/agentwall:setup`): find or install the binary (`install.sh` on macOS/Linux; the release zip into `%LOCALAPPDATA%\agentwall` on Windows, checksum verified), run `agentwall init` and `agentwall init --apply`, show what changed, tell the user to restart Claude Code.
- `plugin/hooks/hooks.json`: a `SessionStart` hook runs `agentwall init --check`; when agentwall is missing it says to run `/agentwall:setup`. Silent when everything is protected.
- Install: `/plugin marketplace add Arsh624/agentwall`, then `/plugin install agentwall@agentwall`.
